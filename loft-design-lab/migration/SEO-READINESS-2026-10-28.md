# LOFT: повторная SEO-проверка и подготовка переноса

Дата: 28 октября 2026 года. Рабочий домен и DNS пока не переключались.

Владелец подтвердил, что текущий хостинг — Vercel, а основной поисковый трафик приходится на главную страницу. Поэтому главный приоритет перед переключением — адрес `/`, его canonical, title/description, индексация и фактическая мобильная загрузка. Название боевого проекта и численные данные Search Console пока не получены.

## Решение по текущему состоянию

Содержимое и структура новой версии подходят для следующего этапа переноса. Однако у обычной тестовой сборки по-прежнему включён `noindex`; её нельзя подключать к рабочему домену без смены профиля и проверки реальных ответов сервера/CDN.

Подготовлен отдельный кандидат `release/loft-production`. Он проходит локальную предварительную проверку, но имеет статус `liveReady: false`: живые домены, хостинг, TLS, доставка заявок и данные Google Search Console ещё не проверены. Этот документ не является обещанием сохранения позиций или отчётом о выполненном переключении.

## Что проверено по исходнику

- Источник: `persimon-pro/loft-creative-house`, `main` = `9eae9fe5a185f548921d98eb80909554397650a7`. GitHub подтвердил этот SHA при повторной проверке.
- Все 132 исходных файла присутствуют; 118 исходных медиа/API/базовых файлов контролируются по точным хешам.
- Сохранены семь известных страниц: `/`, `/production`, `/smm`, `/branding`, `/web`, `/booking-stars`, `/order`.
- Проверяются 1002 исходных языковых блока и 1578 значимых текстовых узлов. Единственная согласованная замена контента — короткий H1 главной «Усиливаем бренды.» / «Brands, amplified.»; оригинал остаётся в неизменённом контрольном снимке.
- У семи страниц уникальные title и canonical; исходные description, OG, Twitter Card и адреса сохранены. JSON-LD разбирается без ошибок.
- Внутренние ссылки и якоря из исходника разрешаются. Неизвестный адрес возвращает настоящий HTTP 404.
- Перенаправление `loft.tj → www.loft.tj` сохраняет путь и параметры запроса. Локальные проверки используют только loopback и не следуют за внешними redirect.

Это подтверждает соответствие зафиксированному репозиторию. Список реально проиндексированных старых URL может быть шире семи страниц; его нужно получить из Search Console/аналитики и сверить отдельно.

## Найденные риски и выполненные изменения

| Область | Факт | Действие |
| --- | --- | --- |
| Индексация | В тестовой сборке `X-Robots-Tag: noindex, nofollow` задан одновременно в Express и Vercel | Обычная сборка остаётся закрытой. Создан отдельный явный производственный профиль; `VERCEL_ENV=production` не используется как разрешение индексации |
| CDN и алиасы | Статические ответы могут обрабатываться Vercel отдельно от Express | В кандидате добавлено условие noindex для всех хостов, кроме точного `www.loft.tj`; официальная схема Vercel проверена, фактическое поведение edge ещё нужно проверить |
| Дубли URL | Локальный Express допускает варианты `.html`, `/index` и завершающий `/` | Кандидат нормализует известные HTML-адреса постоянными перенаправлениями, сохраняет query и не перенаправляет API POST |
| Кеш обновлений | JS использует постоянные имена и прежний длительный кеш | В кандидате JS/CSS требуют revalidation для надёжного обновления и отката |
| FAQ | Шесть вопросов главной находятся только в JSON-LD, без видимого FAQ | Из кандидата удаляется только этот неподдерживаемый FAQPage. Разметка организации и видимого FAQ букинга сохраняется. Исходный снимок не менялся |
| Язык | Форма заявки по умолчанию показывалась на английском при русских SEO-метаданных | Начальный язык и fallback формы приведены к русскому; сохранённый выбор английского работает |
| Надёжность интерфейса | Ошибка доступа к localStorage могла прервать последующие обработчики шести внутренних страниц | Чтение и запись языка защищены; проверены переключение языка и предзаполнение заявки при запрещённом хранилище |
| Начальная загрузка | Пять JPG-постеров команды загружались сразу, хотя блок далеко ниже главной | Добавлена нативная ленивая загрузка видео. Исходные медиа сохранены; в поддерживающих браузерах постеры и ролики запрашиваются возле блока |
| Размеры изображений | У заставки и фона не было явных размеров изображения в HTML | Добавлены фактические width/height с сохранением прежнего CSS-масштабирования |

У старых браузеров без нативного `video.loading` остаётся прежняя ранняя загрузка постеров. Функциональная проверка выполнена в Chromium 154 с настольным и мобильным viewport, а не на физическом iPhone.

В исходной разметке также остаются низкий контраст некоторых подписей футера и скачок уровня заголовков. Они унаследованы от оригинала и не являются доказанной причиной потери позиций. Отдельные англоязычные URL и hreflang не добавлялись: текущий переключатель языка работает на тех же адресах.

## Локальное мобильное сравнение

Lighthouse 13.6.0, один прогон каждой версии, одинаковый мобильный режим. Исходник запущен локально из оригинального репозитория, новая версия — из нового проекта. Это лабораторные данные, не полевые Core Web Vitals и не результаты живого `loft.tj`.

| Метрика | Исходник | Новая до оптимизации | Новая после оптимизации |
| --- | ---: | ---: | ---: |
| Performance | 73 | 85 | 88 |
| FCP | 2,0 с | 2,4 с | 2,4 с |
| LCP | 8,9 с | 2,4 с | 2,4 с |
| Speed Index | 3,0 с | 5,0 с | 2,9 с |
| TBT | 3 мс | 276 мс | 297 мс |
| CLS | 0,055 | 0,001 | 0,001 |
| Передано за прогон | 1,81 МБ | 2,76 МБ | 1,36 МБ |
| Ранние запросы постеров команды | 5 | 5 | 0 |

Убрано около 1,40 МБ ранней передачи данных. Нагрузка JavaScript остаётся выше исходника: главный bundle содержит около 757 КБ без сжатия, около 221 КБ gzip, причём Three.js занимает примерно две трети. TBT — лабораторный показатель, он не заменяет измерение INP реальных посетителей. Разница небольших показателей между одиночными прогонами может быть шумом.

LCP-элементом новой страницы в отчёте оказался текст H1. Его время отрисовки нельзя приравнивать ко времени полного исчезновения заставки; для восприятия движения нужно отдельно учитывать Speed Index и реальное поведение страницы.

Ограничения замера: локальный Express не подтверждает реальное сжатие/кеш Vercel; внешние HTTPS-запросы заблокированы политикой среды; новый тестовый сервер намеренно отдаёт noindex. Поэтому его Lighthouse SEO score 69 не означает потерю SEO на рабочем домене. В реальном выпуске обязательно проверить HTTP-заголовки и URL Inspection. У обеих версий в этом прогоне Accessibility 95 и Best Practices 100; это не полный аудит доступности.

Данные: `migration/seo-audit-2026-10-28-lab.json`. Полные локальные JSON Lighthouse: `release/seo-audit-2026-10-28/`.

## Подготовленный производственный кандидат

```sh
npm ci
npm run check:source
npm run release:prepare
npm run release:check
```

Генератор требует явные профиль `production` и origin `https://www.loft.tj`, копирует только перечисленные runtime-файлы, не переносит секреты/`.env`/node_modules/черновики и не публикует сайт. Обычный `npm run build` не включает производственный профиль.

`release:check` использует официальный `@vercel/routing-utils 6.6.0` и Ajv. Проверяет неизменность всех входов кандидата, индексацию на canonical-host и закрытие остальных, семь страниц, метаданные/schema, redirects/404, robots/sitemap и кеш. Подставленный canonical Host у обычной тестовой сборки не снимает noindex; X-Forwarded-Host не открывает индексацию кандидата на другом хосте. Проверки не отправляют заявки и сообщения.

Локальный результат хранится в `release/loft-production-preflight.json`. Проверка схемы конфигурации не заменяет проверку реального Vercel CDN.

Проверки этой подготовки прошли: сверка исходного содержимого, сборка JS/CSS, официальный routing schema и шесть групп локальных HTTP-проверок кандидата, а также 12 браузерных проверок на настольном и мобильном viewport. Среди них — все семь страниц, русская/английская вёрстка, предзаполнение формы, запрещённый localStorage, отложенная загрузка постеров и автономный WebGL-предпросмотр. Реальные заявки не отправлялись.

## Порядок постепенного переноса

1. Зафиксировать Search Console/аналитику, в первую очередь для главной: целевые запросы, клики, показы, позиции и заявки до изменения. Получить полный список старых посадочных URL.
2. Подтвердить текущий хостинг/проект, сохранить адрес и ID старого деплоя, настройки web-DNS и записи почты. Для переноса сайта не менять nameserver/MX/TXT без отдельной необходимости.
3. Развернуть проверенный кандидат в отдельном рабочем проекте без переназначения `loft.tj`. Проверить все страницы, формы и noindex на выданном техническом домене.
4. Сверить live-заголовки, redirects, canonical, robots/sitemap, 404, Content-Encoding и кеш. Проверить TLS и вариант http/https. Скопировать привязки нужных переменных в хостинге, не передавая секреты в переписке.
5. После проверки и отдельного согласования переключить существующий домен. Сразу проверить основной адрес на отсутствие noindex, остальные технические домены — на его наличие, затем проверить URL Inspection и карту сайта.
6. Сравнивать индексацию, ошибки, трафик и заявки после запуска с исходными данными. Сохранять старый деплой доступным для отката.

Особый функциональный стоп-фактор: исходный обработчик заявки может вернуть success даже без Telegram-токена. Это не доказательство проблемы живого сайта, но привязки новой среды и фактическую доставку нужно проверить отдельно. В рамках этого аудита сообщения не отправлялись.

Если после переключения обнаружатся noindex на основном адресе, недоступные важные страницы, неверный canonical или нарушение приёма заявок, вернуть домен/алиас на сохранённый старый деплой и проверить заголовки повторно. Перед каждым изменением DNS сохранять точные прежние значения.

## Что пока не подтверждено

- Реальный активный деплой `loft.tj`, его DNS/TLS и ответы CDN.
- Полевые LCP/CLS/INP и Google Search Console.
- Полный список поисковых посадочных страниц за пределами известного репозитория.
- Название боевого проекта и готовность привязок приёма заявок.

До подтверждения этих пунктов переключение рабочего домена не выполняется. Новый дизайн, исходные страницы и производственный кандидат сохранены отдельно от действующего сайта.
